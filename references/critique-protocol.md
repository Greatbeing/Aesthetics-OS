# 审美质量审判协议（critique）

> measure 测**结构**，critique 判**质量**。两者分工不可互相替代。
> 本协议必须由**真实视觉**执行（agent 的 vision_analyze、Agnes 多模态、或人眼），
> `scripts/critique.py` 只负责生成提示、校验结构、绑定像素、门禁 verdict——它自己不“看”图，也绝不伪造审判。

## 为什么需要它

形式指纹能抓住“没变”（换皮），但分不清“变美了”还是“变丑了”：一张空洞的米色图和一张精妙的极简构图，`flat_area` 都≈0.99。要判断“高级不高级”，必须有人/模型真的看画面，说出**看见的事实→形式机制→感知效果**。这就是鉴赏家，不是评委打分。

## 审判结构（register 会逐项校验，缺一项即拒绝）

### 一、6 红线（一条都不许踩，每条给看见的证据）

| 编号 | 红线 | 检查点 |
|---|---|---|
| CS | 内容安全 | 无暴力/仇恨/歧视/侵权/未授权肖像 |
| FP | 多指畸形 | 手/趾数量、关节方向 |
| TX | 文字乱码 | 文字可读、语义正确、无错字堆叠 |
| AI | 塑料感 | 皮肤/水面/材质是否过度平滑、磨皮假面 |
| CU | 文化禁忌 | 宗教/民族/历史符号是否被误用 |
| CM | 构图失衡 | 主体贴边、地平线居中切割、头被裁 |

每条判 `pass / warn / fail` 并写证据。**任何一条 fail，结论不得为 pass。**

### 二、三轴坐标（-3 到 +3，对照品味锚点）

- X 理法↔天机：规整模板 ↔ 自然灵动
- Y 饱满↔空灵：堆砌满屏 ↔ 留白气口
- Z 刚↔柔：锐利刺眼 ↔ 柔和温润

给出坐标后，与 `taste-profile.json` 的 `user_taste_coordinates` 比对，偏离要说明是优点还是硬伤。默认锚点 X+2 / Y+3 / Z+1（天机·空灵·柔）。

### 三、5 反射（每条：看见的事实 → 形式机制 → 感知效果）

1. 目的信号：第一眼知道是什么、视线先落在哪
2. 系统一致：色彩/形状/笔法是否服从少量规则
3. 材质真实：光与纹理有无可信来源
4. 具体性：换个名字还能套给别的图吗（能＝模板）
5. 克制：有没有多余的竞争焦点

### 四、结论与优先修改

- `pass` 可交付 / `revise` 建议改 / `reject` 打回
- 非 pass 必须给**一条最优先的具体修改**（不是“更好看”，而是改哪个机制）
- 必须声明 `judge`（谁/什么视觉做的判断）——不接受匿名审判

## 闭环位置

```
生成（执行 Skill）→ measure 测结构 → critique 判质量
   ↑                                      │
   └──── revise：按 priority_fix 改 ←─────┘
                     pass → verdict 才允许签审美通过
```

`verdict --aesthetic pass` 现在要求：最新成品有一份**绑定到该像素哈希**、结论为 pass 的 critique。测过结构≠评过质量；没评过质量，接口不产出“通过”。

## 局限（诚实声明）

- 审判是视觉模型的判断，不是客观真值；不同模型/不同次可能略有出入。
- 它判得了构图/材质/克制/文化，判不了“市场会不会喜欢”“品牌战略对不对”。
- 品味锚点是校准参照，不是美的定义；锚点本身应由用户确认与修订。
